# 公開チェックリスト（satoshi-naimen-hoshuron 用）

Release Manager（Claude Code）が公開ブランチ上で実行し、全項目の結果を diff と
ともに報告する。**push はサトシさんの承認後のみ**（Claude Code の deny rules／Hook
に加え、GitHub 側の branch protection で main への直接 push を禁止しておくこと）。

## 0. 公開成立の5条件（前提）

- [ ] BLOCKER 指摘が未処理ゼロ（audit_log.md で確認）
- [ ] 高リスク命題の全件に出典がある
- [ ] 「未確認」分類の命題が確定表現になっていない
- [ ] 本チェックリストの機械検査を通過
- [ ] サトシさんの承認

## 1. 原稿の後処理

- [ ] 段落ID `[P***]`・命題ID `[C***]` がHTML本文から全て除去されている
- [ ] 調査用の作業コメント・内部メモが混入していない
- [ ] 取材源・内部ファイルパス・非公開情報への言及がない

## 2. 記事HTML

- [ ] 文字コードが UTF-8、`<html lang="ja">` 等の基本構造が既存記事と一致
- [ ] タイトル・日付の形式が既存記事と統一（例: 2026.07.07）
- [ ] `style.css` への参照が正しい
- [ ] 記事内リンクが全て実在するファイル/URLを指す
- [ ] 画像参照が全て実在し、**拡張子と実体形式が一致**している
      （過去に .png 参照で実体 JPEG の事故あり。`file` コマンドで実体確認）

## 3. サイト連携（記事追加時に必ず全部）

- [ ] `index.html` に新記事を追加し、フィーチャー枠・記事数を更新した
- [ ] `rss.xml` に新記事のエントリを追加した（タイトル・リンク・日付の整合）
- [ ] アイキャッチ/ヒーロー画像を追加した場合、参照と実体が揃っている
- [ ] 孤立ファイル（どこからも参照されない画像等）を作っていない

## 4. 機械検査

- [ ] 全内部リンクの死活確認（相対パスの解決）
- [ ] 数字・日付・固有名詞が `checks/fact_check.md` の確認結果と一致
- [ ] 引用文が出典台帳の表記と一致
- [ ] 同一事実の重複記載がない
- [ ] 指定字数・見出し字数の範囲内

## 5. 公開手順

1. 公開ブランチを作成（main 直接作業禁止）
2. HTML・index.html・rss.xml・画像を更新
3. 本チェックリストを実行し、`git diff` を生成
4. サトシさんへ公開前報告（diff＋チェック結果＋残存リスク）
5. 承認後に push → PR → merge（branch protection に従う）

## 拒否テスト（初回導入時・設定変更時）

- [ ] main への直接 push が拒否されるか
- [ ] （ワークスペース側）sources/ への書き込みが拒否されるか
- [ ] RESTRICTED ファイルの外部送信コマンドが止まるか
- [ ] Hook を無効化した場合に気づける運用になっているか
