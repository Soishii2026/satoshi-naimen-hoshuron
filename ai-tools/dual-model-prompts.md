# 二モデル定型プロンプト集（P1〜P9）

**コピペ用テンプレート — 二モデル編集運用マニュアル v2 対応**

使い方: `{{ }}` の部分を差し替えて、指定モデルにそのまま貼る。工程の対応は [`dual-model-manual.md`](dual-model-manual.md) §3 を参照。
共通ルール: **前工程の会話履歴は引き継がず、指定された入力物だけを渡す**（非依存の原則）。

## P1. 論点設計 ｜工程①｜担当: GPT-5.6sol

```
あなたは政治コラムの論説委員です。以下のテーマについて、分析フレームを3案出してください。

テーマ: {{テーマ（例: NATO首脳会合を首相が欠席した判断）}}
筆者の立ち位置: 保守の内側から、数字と論理で問う（身内への迎合はしない）

各案に必ず含めるもの:
1) フレーム名（例:「目的関数を入口で取り違えた」式の、構造を一言で言い切る命名）
2) そのフレームで記事を書いた場合の見出し級の一文
3) 論証に必要になる事実・数値のリスト（この段階では未確認でよい）
4) このフレームの弱点（どこを突かれると崩れるか）

最後に、3案のうち推奨1案とその理由を3行以内で。
```

## P2. 事実ベース構築 ｜工程②｜担当: GPT-5.6sol

```
あなたは政治コラムの調査担当です。以下の論点で記事を書くために必要な事実を、表形式で整理してください。

論点: {{P1で採用したフレームと見出し級の一文}}

表の列: | 項目 | 数値・日付・引用文 | 出典の所在（何を見れば確認できるか） | 確度（高/中/低） |

ルール:
- 出典の所在は「◯◯白書の該当章」「国会会議録の◯月◯日◯◯委員会」のように、人間が確認しに行ける場所を書く
- 確認済みと断定しない。あなたの記憶に基づく数値はすべて確度を正直に付ける
- 記事の主張が依存する数字（核心数値）には行頭に ★ を付ける
- 論点に不利な事実・反対方向のデータも最低2件含める
```

## P4. 相互ファクトチェック ｜工程④・二大勝ち筋その1｜担当: **草稿を書いていない方のモデル**

```
以下は政治コラムの草稿です。あなたは校閲デスクです。本文の主張には同意も反論もしないでください。

やること:
1) 固有の数値・年月日・人名・団体名・引用を全て抜き出し、次の表にする
   | 番号 | 記述（本文の該当箇所を引用） | 分類 | 重大度 | 確認方法の提案 |
   - 分類: [要一次資料確認 / 一般的事実 / 疑わしい] の3値
   - 重大度: 高（間違っていたら記事の主張が崩れる）/ 中 / 低（飾りの数字）
   - 確認方法の提案: 人間が当たるべき一次資料と検索語（例: 国会会議録検索システムで「◯◯」）
2) 論理の飛躍・因果の断定・過度な一般化を最大5点、該当箇所を引用して指摘する

禁止事項:
- 新しい事実の追記、文体・表現の修正提案
- 「確認しました」「事実です」という断定（あなたは所在を示すだけで、確認は人間が行う）
---
{{草稿}}
```

**運用メモ:** 出力の「重大度: 高」は人間が一次資料で必ず確認。分類が執筆モデルの認識と割れたら、マニュアル§4の裁定プロトコルへ。検証表は使い捨てず台帳（checklist末尾）へ転記。

## P5. 敵性読者レッドチーム ｜工程⑤・二大勝ち筋その2｜担当: GPT-5.6sol

```
あなたは3人の批判的読者を順に演じます。対象は以下の政治コラム草稿です。

① 保守派の身内読者（「なぜ味方を撃つのか」と憤る立場）
② 安全保障の政策専門家（数字の解釈の甘さ・定義の曖昧さを突く立場）
③ 進歩派の論客（前提そのものを別方向から崩しに来る立場）

ルール:
- 各人が、最も痛い反論を2つずつ。実名の読者が新聞投書やSNSに書く口調で
- 藁人形禁止。筆者が3秒で言い返せる弱い反論は出さない。筆者が黙る反論だけを出す
- 反論には「本文のどの記述を根拠にしているか」を添える

最後に:
- 「筆者が本文で先回りして潰すべき反論トップ3」を選定し、それぞれ1行で選定理由を付ける
---
{{草稿}}
```

**運用メモ:** 出力がぬるいと感じたら、一度だけ「この反論で筆者は動じない。もっと痛い所を突け」と追い込む（2回以上は不毛）。

## P6. 反映・推敲 ｜工程⑥｜担当: Fable5

```
あなたは産経コラムの筆者本人です。以下の草稿に、校閲指摘とレッドチーム反論を反映して修正稿を作ってください。

やること:
1) 校閲指摘のうち【人間確認の結果】欄が「確定」のものだけ本文に残し、「削除/保留」指示のものは削るか帰属表現（「〜とされる」）に落とす
2) レッドチーム反論トップ3を、本文中で先回りして潰す。反論の存在を認めた上で切り返す形が望ましい（無視や論点ずらしは不可）
3) 文体の格と締めの一言は守る。修正で語りが痩せたら書き直す

出力の最後に「処理結果一覧」を付ける: 指摘番号ごとに [反映/削除/保留] と一言メモ

草稿: {{草稿}}
校閲指摘（人間確認の結果を追記済み）: {{P4の出力＋人間の裁定}}
潰すべき反論トップ3: {{P5の出力の該当部分}}
```

- リード: 1〜2文。数字を読み上げるのではなく、数字が意味するものを言う

## P8. AI西郷 人格監査 ｜横展開｜担当: GPT-5.6sol（Fableが西郷を演じた後に）

```
あなたはAIペルソナの品質監査役です。以下は「AI西郷」プロンプト（規格書）と、実際の対話ログです。
規格からの逸脱を検査してください。本文の思想内容の当否は判定しません。

検査項目:
1) 教えの重複 — 一度引用した教え・逸話・遺訓が、以降の回答で繰り返されていないか（規格の最重要ルール）。重複があれば該当2箇所を引用
2) 回答構造 — 「一 問いの本質／二 南洲の教え／三 現代への助言／四 南洲の一言」の4部構成が守られているか
3) 薩摩語比率 — 標準語7:薩摩3の目安から逸脱していないか（薩摩弁が強すぎる/消えている、の両方向）。逸脱例を引用
4) 人格ドリフト — 私心のなさ・慈悲・簡潔で重い言葉、から外れた応答（説教くささ、現代スラング、攻撃性、冗長）の有無
5) 問い返しルール — 問い返しが一度までに収まり、その後に必ず助言を示しているか

出力: 項目ごとに [合格/要修正] と根拠の引用。最後に総合判定と、プロンプト（規格書）側を直すべき点があれば1つ提案。
---
規格書: {{ai-saigo-prompt.md の全文}}
対話ログ: {{Fableが西郷として応答したログ}}
```

## P9. 英語版展開（二段構え） ｜横展開｜担当: GPT → Fable

```
Translate the following Japanese opinion column into English. Priorities:
1) Factual precision — every number, date, and quote must survive translation exactly
2) Keep the logical skeleton visible (claim → evidence → counterargument → conclusion)
3) Do not polish for style yet; a literal-leaning, accurate draft is the goal
4) Flag any culturally-loaded term (e.g. 保守の本籍, 政界十六夜) with [TN: note] rather than guessing
---
{{本文}}
```

```
Rewrite the following draft translation as an opinion column for an educated international readership
(think: op-ed page of a serious broadsheet). Requirements:
- Resolve each [TN: ...] flag into natural English, keeping the author's conservative-insider stance legible
- Keep every number, date, and quote unchanged
- The closing line must land with the same weight as the Japanese original
- Output: final English text, then a 3-line note listing any nuance you had to trade away
---
{{9aの出力}}
```
